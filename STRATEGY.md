## 2. INVARIANTS

- **Never push `appcast.xml` or `docs/` changes to `main` without explicit task authorization.** Pushing `main` IS the production publish. The tempting shortcut: "commit and push this doc tweak" — it also ships whatever else is staged to the live feed/site. OBSERVED: RELEASING.md step 8.
- **Never edit `appcast.xml` by hand** (formatting cleanup, reordering, "fixing" old items). Sparkle silently rejects items whose `edSignature`/`length` don't match the exact published bytes — a corrupted item shows no error anywhere. Use `scripts/release_lib.py` / `make release`. OBSERVED: appcast header comment, RELEASING.md.
- **Never reuse or decrease `CFBundleVersion`**, even for rollback — supersede with a higher one. OBSERVED: RELEASING.md Rollback.
- **Never run Sparkle's `generate_keys`** on this machine for any reason; it can overwrite the EdDSA private key, permanently bricking auto-update for every install. Never print or export the key. OBSERVED: RELEASING.md.
- **Never hand-edit `project.pbxproj`**; edit `project.yml`, run `make project`. Hand edits are silently clobbered on the next regenerate. OBSERVED: CLAUDE.md, AGENTS.md.
- **Never use `git add -A` / `git add .`** — the tree carries pre-existing untracked files (`hermes_qa_2026-06-21.md`, two untracked sprint plans, `scripts/__pycache__/`) that must not be swept into a commit. Stage explicit paths only. OBSERVED: git status 2026-07-03.
- **Never reintroduce a subprocess or shell into CLI detection** (`which`, `zsh -c`). Detection is pure `FileManager` probing so the auto-start path is correct before `init()` returns. The tempting "fix": detection misses a custom install, so shell out to `which`. Don't — add a probe path or use the Settings override. OBSERVED: CLAUDE.md.
- **Never bypass `validationError(forCLIPath:)`** (binary basename must be `afterwords`) or the 1024–65535 port clamp. They are the security guards for an unsandboxed app with a UserDefaults-writable executable path. OBSERVED: CLIExecutor.swift, security review finding 1.
- **Never add PID/process tracking or make Quit stop the server.** launchd owns the lifecycle; /health polling is the only truth. OBSERVED: CLAUDE.md.
- **Do not weaken HealthMonitor timings or the `pendingStop` guard** (90s startup timeout, 3 consecutive failures, 3s per-request timeout, stale-200 drop after Stop). They look redundant; each blocks a specific false-state bug. OBSERVED: CLAUDE.md invariants section.
- **Do not delete `HealthInfo.init(status:loadedBackends:voices:)`** — the custom `init(from:)` suppresses the memberwise init; tests need the explicit one. OBSERVED: CLAUDE.md Testing.
- **Use `onChange(of:perform:)` (one-argument form)** — deployment target is macOS 13; the two-arg form compiles on your Xcode but violates the floor. OBSERVED: CLAUDE.md conventions.
- **Sparkle stays pinned `exactVersion: 2.9.2`** in project.yml (audit M-3); CI actions stay pinned to full commit SHAs. Do not "helpfully" bump to ranges or tags. OBSERVED: commit 4a765ae, ci.yml comments.
- **Do not add screenshots/temp artifacts to git**: `screen_*.png` is deliberately ignored; use the scratchpad. OBSERVED: .gitignore.

- **Shortcut**: trust `git status` noise cleanup — delete or commit `hermes_qa_2026-06-21.md`, untracked plans, `__pycache__/`. **Tell**: `git add` with a path you didn't create this task. **Correction**: leave untracked files untouched; they are evidence or the user's WIP.
- **Shortcut**: believe a QA/audit doc over live state (Hermes report says junk files are tracked). **Tell**: a doc claim contradicts `git ls-files`. **Correction**: live git state wins; this specific conflict is documented-stale, act on git.
- **Shortcut**: declare success because `xcodebuild` exited 0 after editing `project.yml` without `make project`. **Tell**: pbxproj diff is empty after a project.yml change. **Correction**: run `make project`; commit the regenerated pbxproj together with project.yml.
- **Shortcut**: assume a CLI command worked because `Process` launched. **Tell**: code asserting server state right after `afterwords start`. **Correction**: state changes come only from HealthMonitor polls; tests use `simulateHealthResult(info:error:)`.
- **Shortcut**: appcast "looks valid" so the release works. **Tell**: you edited appcast fields manually. **Correction**: `python3 scripts/release_lib.py validate appcast.xml` AND byte-length/signature must come from `sign_update` output verbatim; Sparkle rejects silently otherwise.
- **Shortcut**: add a handy "speak clipboard" or history feature. **Tell**: any new audio path besides fixed-phrase samples. **Correction**: scope-frozen; propose as an issue instead.

## 5. ESCALATION TRIGGERS

Stop the gated action, continue safe prep (diagnosis, patch, dry-run output, exact commands):

- Drift between sources of truth beyond the documented-stale items above.
- Anything destructive/irreversible: deleting tags, GitHub Releases, release-manifest files, Keychain entries; rewriting `main` history.
- Scope creep past the frozen user-facing surface in CLAUDE.md.
- Stale time-sensitive facts (version baseline, signing posture) when a task depends on them.
- **Publishing**: `git push origin main` (ships appcast + site), `git push` of tags, `gh release create/edit/delete`, `make release ... PUBLISH=1`, any edit under `docs/` intended to go live. All are production mutations — escalate unless the current task explicitly authorizes that exact action.
- **Secrets/keys**: any operation reading, exporting, backing up, or regenerating the Sparkle EdDSA key (Keychain service `https://sparkle-project.org`). `generate_keys` is forbidden outright. Note: even dry-run `make release` invokes `sign_update`, which reads the private key — allowed, but say so in your report.
- **Doctrine/evidence files**: edits to the files classified in §1 unless the task names them.

Side-effect classes: local reads, `make project/build/test/dmg`, `release_lib.py` validation, unit tests — **allowed**. Dry-run `make release VERSION=x` — allowed (builds, signs via Keychain, reverts bump; publishes nothing). Tag/release/push/appcast/site publish — **escalate**. `generate_keys` — **forbidden**.

A task blocked only on publish is not human-blocked: finish the build, validation, printed appcast item, SHA manifest content, and rollback notes, then request the specific approval.
